# アプリケーション構築タスク

## 目的

AWS ECS 上で起動する Embedded Infinispan アプリケーションを構築し、ALB 経由で JSON API による分散キャッシュの新規追加・取得・更新を実行できるようにする。

## 成果物

- Embedded Infinispan を組み込んだ Java アプリケーション
- JSON API
- 複数 Distributed Cache の設定
- S3 Ping によるクラスターメンバー検出設定
- CloudWatch Logs に出力される操作ログ
- Dockerfile とローカルビルド手順

## タスク

### A1. API アプリケーションの方式決定

- [ ] 既存 Maven プロジェクトを Web API 化する方式を決める。
- [ ] 利用する HTTP フレームワークを決める。
- [ ] Java 17 でコンテナ実行できる起動方式を決める。
- [ ] ローカル実行、ECS 実行で同じ設定値を環境変数から受け取れるようにする。

完了条件:

- アプリケーションの起動コマンドが明確になっている。
- `/api/get/<CACHE_NAME>/<key>` 相当の API を実装できる構成になっている。

上記の項目は、いずれもSpringBootを利用することで可能である。ローカル実行の場合、ministackを利用してS3のエミュレーションが行えれば、docker composeを用いた起動でローカル試験を行う。不可能であれば、ローカルテストとAWSでのテストはinfinispanの設定ファイルを分けて行うものとする。

### A2. JSON API 実装

- [ ] `GET /api/get/{cacheName}/{key}` を実装する。
- [ ] `POST /api/get/{cacheName}/{key}` を実装する。
- [ ] `POST` は `Content-Type: application/json` の任意 JSON を受け取り、指定キャッシュとキーに保存する。
- [ ] `GET` は保存済み JSON を `application/json` で返す。
- [ ] キーが存在しない場合の HTTP ステータスを決めて実装する。
- [ ] 不正なキャッシュ名、不正 JSON、内部エラーのレスポンス形式を決めて実装する。

完了条件:

- curl で JSON の新規追加、取得、更新ができる。
- API レスポンスが試験スクリプトから機械的に検証できる。

### A3. Embedded Infinispan 分散キャッシュ設定

- [ ] キャッシュ名の一覧を設定化する。
- [ ] 各キャッシュを `DIST_SYNC` で作成する。
- [ ] 各キャッシュの `owners` を設定化する。
- [ ] ECS タスク数が `owners` より多い構成で動作することを前提にする。
- [ ] JSON 値を保存できるシリアライズ方式を決める。
- [ ] 起動時にキャッシュを作成または取得する初期化処理を実装する。

完了条件:

- 少なくとも複数キャッシュで同じ API 操作ができる。
- キャッシュごとに `owners` を確認できる。

### A4. S3 Ping 対応

- [ ] Infinispan/JGroups の AWS S3 Ping に必要な依存関係を確認して追加する。
- [ ] S3 Ping 用のバケット名、リージョン、プレフィックスを環境変数から受け取る。
- [ ] ECS タスクが同じクラスタ名で参加するように設定する。
- [ ] ローカル実行時と AWS 実行時でクラスタ検出方式を切り替えられるようにする。

完了条件:

- ECS の複数タスクが同一 Infinispan クラスターに参加できる設定になっている。
- S3 Ping の設定値がコードに固定されていない。

### A5. 操作ログ実装

- [ ] 新規追加、取得、更新のログを出力する。
- [ ] ログには最低限、操作種別、キャッシュ名、キー、結果、タスク識別子を含める。
- [ ] JSON 本文をログに出すかどうかを決める。
- [ ] CloudWatch Logs で検索しやすいログ形式にする。

完了条件:

- ECS タスクのログから、どのタスクでどの操作が処理されたか確認できる。

### A6. Docker 化

- [ ] Dockerfile を作成する。
- [ ] Maven ビルド済み成果物をコンテナに含める。
- [ ] アプリケーションポートを公開する。
- [ ] ヘルスチェック用エンドポイントを実装または指定する。
- [ ] ローカルで Docker イメージをビルドして起動確認する。

完了条件:

- `docker build` と `docker run` で API が起動する。
- ヘルスチェックが成功する。

### A7. アプリケーション単体確認

- [ ] ローカル JVM 実行で API を確認する。
- [ ] ローカル Docker 実行で API を確認する。
- [ ] 複数プロセスまたは複数コンテナでクラスター形成を確認する。
- [ ] 複数キャッシュに対する JSON の書き込み、読み取り、更新を確認する。

完了条件:

- AWS デプロイ前に、API とキャッシュ操作の基本動作が再現できる。
