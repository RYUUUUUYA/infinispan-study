# 試験スクリプト作成及び実行タスク

## 目的

ALB 経由で JSON API を繰り返し呼び出し、複数 ECS タスク上の Embedded Infinispan 分散キャッシュで新規追加、取得、更新が期待通り動作することを確認する。

## 成果物

- AWS 環境向け試験スクリプト
- 試験データ生成ロジック
- 実行手順
- 試験結果ログ
- CloudWatch Logs 確認観点

## 試験対象 API

```text
GET  /api/get/<CACHE_NAME>/<key>
POST /api/get/<CACHE_NAME>/<key>
Content-Type: application/json
```

## タスク

### T1. 試験方針整理

- [ ] 試験対象キャッシュ名を決める。
- [ ] キャッシュごとの投入件数を決める。
- [ ] 読み取り繰り返し回数を決める。
- [ ] 更新繰り返し回数を決める。
- [ ] 更新直後に古い値が一時的に読める場合のリトライ方針を決める。
- [ ] スクリプトの成功条件と失敗条件を決める。

完了条件:

- スクリプトが何をもって成功とするか明確になっている。

### T2. 試験スクリプト設計

- [ ] ALB ベース URL を引数または環境変数で受け取る。
- [ ] キャッシュ名一覧を引数または環境変数で受け取る。
- [ ] 投入件数、取得回数、更新回数を設定化する。
- [ ] JSON ペイロードをキーごとに一意に生成する。
- [ ] API レスポンス JSON を比較できるようにする。
- [ ] エラー時に対象 URL、HTTP ステータス、期待値、実値を出力する。

完了条件:

- AWS 環境が変わっても URL と件数設定だけで再実行できる。

### T3. 新規追加試験の実装

- [ ] 各キャッシュに対して十分な件数のキーを作成する。
- [ ] `POST /api/get/{cacheName}/{key}` で JSON を登録する。
- [ ] 登録結果の HTTP ステータスを検証する。
- [ ] 登録した期待値をローカルの検証用データとして保持する。

完了条件:

- 全キャッシュに対して期待件数の新規追加が成功する。

### T4. 読み取り試験の実装

- [ ] 各キャッシュ、各キーに対して `GET` を複数回実行する。
- [ ] 取得 JSON が登録時の期待値と一致することを検証する。
- [ ] ALB の振り分けを確認しやすいように連続アクセスする。
- [ ] 失敗時は対象キャッシュ、キー、試行回数を出力する。

完了条件:

- 新規追加した全キーを複数回読み取っても期待値と一致する。

### T5. 更新試験の実装

- [ ] 各キャッシュ、各キーに対して更新用 JSON を作成する。
- [ ] `POST /api/get/{cacheName}/{key}` で更新する。
- [ ] 更新後に `GET` を複数回実行する。
- [ ] 古い値が一時的に読める場合は、決められた回数までリトライする。
- [ ] 最終的に更新後 JSON と一致することを検証する。

完了条件:

- 全キャッシュの全キーで、最終的に更新後の期待値を取得できる。

### T6. ログ確認手順の作成

- [ ] CloudWatch Logs で新規追加ログを確認する手順を作る。
- [ ] CloudWatch Logs で取得ログを確認する手順を作る。
- [ ] CloudWatch Logs で更新ログを確認する手順を作る。
- [ ] 複数 ECS タスクで処理されていることを確認する観点を作る。
- [ ] エラー発生時に見るべきログ項目を整理する。

完了条件:

- 試験結果と CloudWatch Logs を突き合わせて、API 操作が複数タスクで処理されたことを説明できる。

### T7. AWS 環境での実行

- [ ] ALB DNS 名を取得する。
- [ ] ECS サービスの全タスクが healthy であることを確認する。
- [ ] 試験スクリプトを実行する。
- [ ] スクリプトの標準出力と終了コードを保存する。
- [ ] CloudWatch Logs の確認結果を保存する。
- [ ] 失敗があった場合は原因を分類する。

完了条件:

- 試験スクリプトが成功終了する。
- 実行結果から、新規追加、取得、更新の動作確認結果が追跡できる。

## 推奨スクリプト仕様

```text
入力:
  ALB_BASE_URL
  CACHE_NAMES
  ITEM_COUNT
  READ_REPEAT
  UPDATE_READ_RETRY

出力:
  追加成功件数
  読み取り成功件数
  更新成功件数
  失敗したキャッシュ名、キー、期待値、実値
  試験開始時刻、終了時刻

終了コード:
  0: 全試験成功
  1: API 検証失敗
  2: 設定不備
  3: 通信エラー
```
